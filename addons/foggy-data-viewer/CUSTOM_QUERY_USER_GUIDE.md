# 自定义查询操作手册

## 1. 功能简介

自定义查询用于保存和复用个人的列表查询偏好，包括：

- 表格展示哪些字段，以及字段顺序、列宽和固定位置
- 查询条件、条件组和条件值
- 排序方式
- 每页显示条数

查询方案保存后，可以直接应用、编辑、覆盖、设为默认，也可以通过标准 JSON 分享给其他用户。

> 查询方案只保存用户的查询偏好。数据权限、页面固定条件和后端权限仍由业务系统控制。
>
> 本手册对应当前界面：查询方案列表中的编辑、分享快捷图标在鼠标移入方案行后显示。

## 2. 从哪里进入

在列表页面顶部点击 **查询方案**，可以看到以下功能：

| 功能 | 用途 |
| --- | --- |
| 自定义查询 | 新建一个查询方案 |
| 查询管理 | 查看、应用、编辑或删除已有方案 |
| 导入分享 | 导入其他用户发来的标准 JSON |
| 保存查询 | 直接保存当前列表状态 |
| 可用查询 | 快速应用已有方案 |
| 清空查询条件 | 清除用户当前设置的条件，页面固定条件不受影响 |

## 3. 新建查询方案

### 第一步：选择展示字段

进入 **查询方案 → 自定义查询** 后，首先进入“选择展示字段”。

左侧是当前已选字段，右侧是可选字段。

#### 选择和移除字段

- 点击右侧字段卡片，可以加入或移出展示列。
- 可以按字段名称搜索，也可以按文本、选项、日期、日期时间、数值筛选。
- 左侧显示当前字段数量，最多配置 50 个展示字段。
- 页面要求的锁定字段会自动保留，不能删除。

#### 调整字段顺序

- 将已选字段拖到目标字段上方或下方：插入到对应位置。
- 将已选字段拖到目标字段中部：与目标字段交换位置。
- 将右侧未选字段直接拖到左侧：只会插入，不会替换已有字段。
- 拖到左侧列表末尾：追加到最后。
- 也可以选中字段后使用 `Alt + ↑` 或 `Alt + ↓` 调整顺序。

拖动过程中会显示蓝色插入线或交换背景；操作完成后，被调整的字段会短暂高亮。

#### 设置列宽和固定位置

点击已选字段右侧的编辑图标，可以设置：

- 列宽
- 左固定或右固定
- 恢复默认设置
- 移到顶部或底部

### 第二步：设置查询条件

点击 **下一步：设置查询条件**。

#### 添加条件

每条条件包含：

1. 查询字段
2. 匹配方式
3. 条件值

同一个条件字段可以出现多次。例如，可以同时设置：

- 开单日期大于等于某一天
- 开单日期小于某一天

系统不会因为字段重复而阻止保存。

#### 添加条件组

条件可以放在不同逻辑组中：

- **AND / 全部同时满足**：组内条件必须同时满足
- **OR / 任一满足**：组内任意条件满足即可

空条件组不能保存。请先添加条件，或删除空组。

#### 不同类型的条件值

| 字段类型 | 操作方式 |
| --- | --- |
| 文本 | 直接输入文本；多个值通常用逗号分隔 |
| 字典/选项 | 从下拉选项中选择；多选会按 `IN` 执行 |
| 数值 | 输入数字，可设置等于、大于、小于、范围等匹配方式 |
| 日期 | 选择今天、昨天、最近 7 天等相对日期，或选择具体日期 |
| 日期时间 | 选择开始和结束时间，或使用相对时间范围 |
| 成员/站点 | 从业务系统提供的成员或站点选项中选择 |

日期类的“今天”“昨天”等相对值会作为相对日期保存，在实际查询时按照当前时间重新计算。

#### 空条件如何处理

空条件可以暂时保留在方案中：

- 保存方案时不会强制要求每个条件都填写
- 执行查询时，空条件会自动忽略
- 后续可以回到编辑页面继续补充

如果希望条件立即生效，请填写条件值；如果不需要该条件，可以删除它。

用户条件最多 20 条，条件组本身不单独占用条件数量，但组内叶子条件会计入数量。

### 第三步：确认并保存

点击 **下一步：确认与保存**：

- 方案名称为必填项
- 方案说明为可选项
- 勾选“保存后立即应用”，保存完成后会立即使用该方案查询

默认保存为个人方案。保存后，其他用户不会自动看到该方案；分享给其他用户时，对方需要导入并重新保存。

## 4. 应用和管理查询方案

### 快速应用

点击 **查询方案**，在“可用查询”中点击方案名称即可应用。

应用后，以下内容会同步到列表：

- 展示字段
- 字段顺序、列宽和固定位置
- 查询条件及条件值
- 排序方式
- 分页大小

页面固定条件和运行时必需字段仍由系统自动处理，不会被个人方案覆盖。

### 查询管理

进入 **查询方案 → 查询管理**，可以：

- **应用**：使用该方案
- **编辑方案**：从第一步重新检查字段，再修改条件和方案名称
- **覆盖当前**：用当前列表状态覆盖已有方案内容
- **设为默认**：将方案设为当前用户在此页面的默认方案
- **删除**：删除方案

方案行上的编辑和分享图标默认隐藏。鼠标移到方案行上后，会显示两个快捷图标：

- 铅笔图标：编辑方案
- 分享图标：导出分享 JSON

## 5. 分享和导入分享

### 分享方案

有两种入口：

1. 在查询管理中，将鼠标移到方案行，点击分享图标
2. 进入查询管理后，点击方案右侧的“分享”操作

分享窗口提供：

- **复制 JSON**：复制到企业 IM、邮件或其他沟通工具
- **下载 JSON**：下载为 `custom-query-share.json` 文件

标准分享包版本为 `custom-query-share.v1`。

分享包只包含可跨用户传递的查询内容，不包含：

- 用户 ID
- 方案 ID
- 权限范围
- 创建人/更新时间
- 其他引擎内部归属信息

### 导入分享

1. 在目标列表页面点击 **查询方案 → 导入分享**。
2. 粘贴收到的 JSON 内容。
3. 点击 **校验并载入**。
4. 确认字段、条件和方案名称。
5. 点击保存，方案会保存到当前用户名下。

导入不会直接覆盖当前方案，也不会自动修改发送人的方案。

### 导入校验规则

- 分享包的 QM 必须与当前页面 QM 一致。
- 如果页面配置了菜单 ID 或 URL，还会校验页面上下文。
- QM 或页面上下文不一致时，系统会阻止导入，避免把 A 页面方案误导入 B 页面。

TMS 接入时，建议至少传入稳定的菜单 ID；URL 可以作为补充校验信息。

## 6. 常见问题

### 为什么选了“昨天”，保存后列表里显示的不是昨天？

“昨天”是相对日期。方案保存的是相对值，实际查询时会根据当前时间计算具体日期边界。编辑方案时仍会显示“昨天”。

### 为什么选择了字典或站点，表格条件没有显示？

请确认：

1. 选中的是有效的字典/站点成员；
2. 已点击保存或应用；
3. 当前页面 QM 与方案 QM 一致；
4. 该字段在页面元数据中仍然可用。

### 为什么导入分享失败？

常见原因：

- JSON 不完整或格式错误；
- 分享包版本不受支持；
- 分享包来自其他 QM；
- TMS 配置的菜单 ID 或 URL 不一致；
- 分享方案中的字段已不在当前 QM 中。

### 为什么空条件没有过滤数据？

这是预期行为。空条件会保留在方案中，但执行查询时会自动忽略。填写值后，该条件才会参与查询。

### 为什么页面还有条件，清空查询条件后仍然存在？

页面固定条件不属于用户条件。例如“只显示已签收运单”可能由页面业务规则自动追加，清空查询条件不会删除这类固定规则。

## 7. 推荐使用流程

日常使用建议按以下顺序操作：

1. 先在第一步整理展示字段和顺序；
2. 在第二步添加必要条件，暂时不确定的条件可以留空；
3. 在第三步保存并立即应用；
4. 后续优先从“可用查询”快速应用；
5. 需要修改时使用行上的编辑图标；
6. 需要给同事使用时导出 JSON，由对方在相同 QM 页面导入并另存。

## 8. TMS 页面接入说明

前端组件配置示例：

```ts
{
  userId: currentUserId,
  model: 'YourQueryModel',
  businessKey: 'your-table-instance',
  shareContext: {
    menuId: 'tms.your-menu',
    url: location.pathname
  }
}
```

其中：

- `model` 是必须的 QM 身份，也是分享导入的最低校验边界；
- `menuId` 建议使用稳定的 TMS 菜单 ID；
- `url` 可用于补充页面校验；
- 分享导入后的方案仍由当前用户保存和管理。
