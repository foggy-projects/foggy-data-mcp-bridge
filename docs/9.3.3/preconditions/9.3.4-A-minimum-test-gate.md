# 9.3.4-A Minimum Test Gate for 9.3.3

## 文档作用

- doc_type: precondition
- intended_for: build/test owner / 9.3.3 execution agent / reviewer
- purpose: 只建立足以可信验证生命周期并发的最小门，不提前宣布完整 9.3.4 已完成。

## 必须交付

版本路线图和本 gate 的“必须实际运行测试”是 9.3.3 的交付标准；root `CLAUDE.md` 中旧的“不需要运行单元测试”描述不适用于本次正式并发证据。

### A. 最小 Surefire/Failsafe 分层

- Surefire 负责 unit/legacy test，并明确排除本轮新增 `*IT`/`*E2E`。
- Failsafe 在 `integration-test/verify` 运行本轮新增 `*IT`，同一 class 不得被两个 runner 重复执行。
- 本轮不批量重命名全仓历史 `*IntegrationTest`；9.3.4 再完成全量迁移。

### B. No-test Fail Closed

- 目标 lifecycle unit suite 为 0、指定 class 不存在或 Failsafe IT 为 0 时命令失败。
- reactor `-am` 的 helper module 可以没有指定测试，但 wrapper 必须校验 owning module 的实际 XML report/class/count，不能靠 `surefire.failIfNoSpecifiedTests=false` 报绿。
- evidence 必须同时保留一次预期失败和一次真实 suite 通过记录。

### C. Required DB Preflight

- 9.3.3 lifecycle gate 的 required external DB：MySQL 5.7 与 PostgreSQL 15；SQLite 用于快速真实查询。
- preflight 不只检查端口，必须通过 JDBC 读取 product name、真实 version、URL/catalog/schema 的非敏感 identity，并验证 sentinel fixture。
- DB 不可达、产品错误、版本不符合或连到错误 fixture 时，在测试前失败。
- SQL Server 与 MySQL 8 的完整 required matrix 仍归 9.3.4；9.3.3 收口继续跑既有 SQL Server 回归以防退化。

### D. Deterministic Concurrency Harness

- 使用 latch/barrier/phaser、受控 loader 和 bounded timeout，不以 `Thread.sleep` 决定交错。
- 能记录 build count、并发重叠、before/after generation、observed result set、timeout/deadlock。
- executor 在每个用例后关闭，并断言无残留 in-flight/task/ThreadLocal。

### E. Dedicated Gate Entry

- 提供单一可复跑入口，目标形态：`mvn ... verify` + required DB preflight script/workflow。
- workflow/report 必须能证明 unit 和 IT 实际各运行一次，且上传/保留报告路径；完整 release immutable artifact 归 9.3.4。

## 非目标

- 不消除 release workflow 中全部 `--skip-external-db` / `-DskipTests` 通道。
- 不建立 SQLite、MySQL 5.7、MySQL 8、PostgreSQL、SQL Server 完整 required matrix。
- 不冻结全仓覆盖率基线、skip budget 或 release artifact 格式。
- 上述项目全部由 9.3.4 正式收口。
