# 9.0.0 Pivot 引擎实现技术栈评估报告

在 9.0.0 的“战役二：引擎编译逻辑的重构”中，为了实现从多维透视 DSL 到关系型 SQL 的翻译（特别是处理骨架生成、稀疏补全和复杂 Rollup），我们对目前主流的开源生态进行了评估。

## 一、 评估方向与结论

传统的 Java ROLAP 引擎（如 **Mondrian**）由于强依赖 XML 配置、架构沉重且与现代 Headless BI 生态脱节，被明确排除在候选名单之外。我们需要的是现代化、轻量级、且能与当前编排引擎无缝融合的技术选型。

## 二、 Python 生态参考（轻量级、现代化）

### 1. MetricFlow (强烈推荐参考)
* **来源：** dbt Labs 收购的现代语义层引擎。
* **特性：** 纯 Python 实现，摒弃 MDX，采用声明式的 YAML/JSON 协议。
* **参考价值：** 它极其完美地解决了一旦脱离单表查询后，底层的维度发散（Fan-out）、复杂交叉关联计算的问题。对于我们如何将前端的透视请求转化为底层安全的带有关联的 SQL 树，它的源码是最好的教科书。

### 2. SQLGlot
* **来源：** Python 圈最强力的 AST 操作与方言转译库。
* **参考价值：** 如果决定用 Python 自研透视编译引擎，应坚决避免手拼 SQL 字符串。SQLGlot 提供了一流的 AST 构建器，可以非常优雅地生成结构化的骨架和 Left Join 代码，并安全的转换为目标数据库方言。

## 三、 Java 生态参考（偏重底层结构）

### 1. Apache Calcite
* **特性：** 动态数据管理与关系代数框架，业界标杆。
* **参考价值：** 若要底层处理非常极端的 `GROUPING SETS / ROLLUP` 并保证生成最高效的查询计划，Calcite 的关系代数树是最终极的解法，但其学习曲线过于陡峭。

## 四、 跨语言的协议设计标杆

### 1. Cube (Cube.dev)
* **特性：** Node.js / Rust 构建的顶级 Headless BI 开源项目。
* **参考价值：** 它的 JSON Query API 是目前对 LLM 和前端开发极其友好的标杆。它的 `measures`, `dimensions`, `timeDimensions` 的平铺设计，为我们的 PivotDSL 设计提供了完美的非 MDX 路线指引。

### 2. Malloy
* **特性：** TypeScript 编写的去 SQL 化现代数据语言。
* **参考价值：** 专门为嵌套/树状结构查询设计，对于构思“如何设计不扁平的 Result Set 契约”具有极大的启发意义。
