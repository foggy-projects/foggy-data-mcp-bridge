# 阶段1开发提示词

## 阶段目标
- 实现 `QM + fieldName -> synthetic member-QM` 的解析规则
- 实现 synthetic member-QM 的命名规则：`${qmName}#${dimFieldBase}`
- 实现根维度自身字段与内嵌子维度递归展开的 schema 生成
- 明确并实现父子维路径节点的保留字段识别策略

## 设计约束
- 只考虑 `REFERENCE_QM`
- 不考虑 `context permission`
- 不做“当前业务事实数据中是否存在该成员”的裁剪
- synthetic member-QM 只允许暴露“根维度 + 内嵌子维度子树”相关字段
- 根维度自身字段使用 canonical 命名：
  - `id`
  - `caption`
  - `TM该维度全部属性`
- 子维度按相对路径展开：
  - `<relativePath>$id`
  - `<relativePath>$caption`
  - `<relativePath>$property`
- 不允许使用泛化的 `child$...` 命名
- 如果某一路径节点本身为父子维，保留字段使用：
  - 根维度：`parentId` / `depth` / `hasChildren`
  - 子维度：`<relativePath>$parentId` / `<relativePath>$depth` / `<relativePath>$hasChildren`

## 建议实现范围
- 补齐 synthetic member-QM 的解析与 schema 生成代码
- 优先复用现有 QueryModel / DbDimension / 嵌套维度递归能力
- 为后续阶段预留 metadata / cache / facade 接入所需的数据结构，但阶段1不强求打通完整查询执行

## 验收标准
- 给定 `model + fieldName`，可稳定解析出唯一 synthetic member-QM 名称
- 根维度自身字段至少包含 `id/caption/TM全部属性`
- 内嵌子维度可按相对路径稳定展开
- 父子维路径节点可识别并标记保留字段
- namespace 下解析结果稳定，不与原 QM 命名冲突
