# 阶段2开发提示词

## 阶段目标

- 让 simple 入口与 DSL 入口统一落到 synthetic member-QM
- 复用现有 `QueryFacade -> beforeQuery -> SQL 生成/执行` 主链
- 不再为维度成员查询新增独立旁路执行路径

## 本阶段范围

- 把 synthetic member-QM 从“解析结果”推进到“可被主查询链识别和装载的内部模型”
- 明确 simple 入口如何把 `model + fieldName` 归一成 synthetic model
- 明确 DSL 入口如何直接使用 synthetic model 名称
- 保持阶段 1 的 schema 规则不变

## 设计约束

- 只考虑 `REFERENCE_QM`
- 不考虑 context permission
- 不做“当前业务数据里是否存在该成员”的裁剪
- 仍然只允许访问“根维度 + 内嵌子维度子树”字段
- 不在本阶段实现外部权限 patch 合并
- 不要求本阶段完成完整缓存与热加载失效闭环，那是阶段 5 范围

## 推荐实现方向

- 优先在 `QueryModelLoader` 或其相邻装载层识别 synthetic member-QM 名称
- 为 synthetic member-QM 生成运行时 QueryModel，并保证其：
  - 可进入 `beforeQuery`
  - 可进入 SQL 构建
  - 不泄漏其他维度、度量、业务字段
- simple 入口不要自己拼 SQL，应归一成 DSL/QueryFacade 能识别的请求
- 旧的维度成员查询旁路如果暂时不能删除，可先保留，但新路径不得再依赖它作为主实现

## 验收标准

- simple 入口与 DSL 入口的最终执行模型一致
- synthetic member-QM 可被正常装载并进入主查询 pipeline
- 可通过现有 SQL 生成能力输出 synthetic member-QM 的 SQL
- 新主路径不再依赖旧维度成员旁路作为核心执行链

  - 旧旁路不再是新主路径依赖
