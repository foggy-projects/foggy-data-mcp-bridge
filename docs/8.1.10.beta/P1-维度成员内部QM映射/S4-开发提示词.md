# Stage4 开发提示词：外部权限 patch 合并

## 目标
- 在不引入内部复杂角色权限体系的前提下，为 synthetic member-QM 增加“外部权限 patch”合并能力。
- 让 simple 入口与 DSL 入口都能接收同一套 patch 语义，并在进入 QueryFacade 主链前完成求交与合并。

## 范围
- 只做 `8.1.10.beta` MVP：
  - `visibleColumns`
  - `forcedSlice`
  - `forcedOrderBy`
- patch 只作用于 synthetic member-QM。
- 不解析 Odoo 等外部系统的角色模型，只接收其已翻译完成的 patch。

## 约束
- 不新增旁路执行链路。
- 不破坏现有普通 QM 查询。
- 所有能力必须落在现有 `QueryFacade -> beforeQuery -> SQL 生成/执行` 主链。
- 开发过程中必须把关键实现日志写入 `docs/8.1.10.beta/P1-维度成员内部QM映射/dev-logs/`。
- 开发过程中必须把测试命令、结果、覆盖率写入 `docs/8.1.10.beta/P1-维度成员内部QM映射/test-records/`。

## 推荐实现方向
- 定义一个轻量 external patch 载体，优先复用 `ModelResultContext.extData`。
- 在 `beforeQuery` 前半段或 synthetic model 解析完成后执行 patch 合并。
- 合并规则至少覆盖：
  - `effectiveColumns = request.columns ∩ visibleColumns`
  - `effectiveSlice = forcedSlice AND request.slice`
  - `effectiveOrderBy = request.orderBy 中属于 visibleColumns 的部分，再叠加 forcedOrderBy`
- 如果请求列被全部裁空，返回明确用户提示，不静默放开。

## 验收标准
- synthetic member-QM 可接收 external patch 并稳定求交。
- `visibleColumns` 可裁剪返回列，且不会放出 member-tree 外字段。
- `forcedSlice` 可与请求 slice 合并，并进入最终 SQL。
- `forcedOrderBy` 可在请求排序后稳定追加或覆盖，行为可预期。
- simple 入口与 DSL 入口都能命中同一 patch 合并逻辑。

## 建议测试
- `visibleColumns` 只保留 `id/caption` 时，请求额外路径字段应被裁掉。
- `forcedSlice` 限制某个嵌套子维属性时，结果应与原生 SQL 一致。
- `forcedOrderBy` 注入后，返回顺序应可预测。
- simple 入口归一后也应命中相同的 patch 合并行为。
