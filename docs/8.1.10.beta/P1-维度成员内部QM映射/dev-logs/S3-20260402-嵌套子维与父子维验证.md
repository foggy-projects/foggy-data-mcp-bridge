## 本阶段目标
- 验证 synthetic member-QM 对根维度属性、一级/二级嵌套子维字段的查询能力
- 验证父子维在 synthetic member-QM 上的层级操作符是否可工作
- 用运行时 SQL 和结果比对确认 member-QM 已稳定落在“维度表 root”语义上

## 关键实现与调整
- 继续沿用 Stage2 建立的 synthetic member-QM runtime factory，不再新增旁路执行链路。
- 保持 `id` 绑定维度主键列，确认 canonical `id` 语义不是业务属性列。
- 运行时测试补齐以下场景：
  - 根维度 canonical 字段查询
  - 一级/二级嵌套子维路径字段查询
  - 子维路径字段过滤与排序
  - 父子维 `descendantsOf / ancestorsOf / selfAndAncestorsOf / childrenOf` 查询
  - simple 入口在父子维字段上的 synthetic 归一

## 关键日志摘录
- synthetic model 运行时构建：
```text
synthetic member-QM build: model=FactSalesNestedDimQueryModel#product
schemaFields=[id, caption, productId, brand, unitPrice, productCategory$id, ...]
queryColumns=[id, caption, productId, brand, unitPrice, productCategory$id, ...]
```

- 嵌套子维过滤与排序 SQL：
```sql
select d2.product_key "id",
       d2.product_name "caption",
       d2.brand "brand",
       d3.category_name "productCategory$caption",
       d4.group_type "productCategory$categoryGroup$groupType"
from dim_product_nested d2
left join dim_category_nested d3 on d2.category_key=d3.category_key
left join dim_category_group d4 on d3.group_key=d4.group_key
where d4.group_type = ?
order by d3.category_name ASC, d2.product_name ASC
```

- 父子维 descendantsOf SQL：
```sql
select d7.team_id "id",
       d7.team_name "caption",
       d7.parent_id "parentId",
       d7.team_level "teamLevel"
from dim_team d7
left join team_closure d8 on d7.team_id=d8.team_id
where d8.distance > 0
  and d8.parent_id = ?
order by d7.team_name ASC
```

## 调试结论
- 当前 synthetic member-QM 的 `id` 语义是“维度主键”，不是业务编码属性。
- 嵌套子维路径字段不需要额外 JOIN 机制，复用现有 QueryObject/JoinGraph 即可。
- 父子维 hierarchy operator 已能在 synthetic model 的 `id` 上复用现有 closure 查询逻辑。
