## 核心改动

- 新增 synthetic member-QM 的阶段 1 元数据结构：
  - 字段类型定义
  - 字段 schema
  - 路径节点
  - schema 视图
  - 解析结果 descriptor
- 实现 `QM + fieldName -> synthetic member-QM` 解析器，输出：
  - `syntheticModelName`
  - `dimensionFieldBase`
  - `matchedNodePath`
  - 递归展开后的 schema
- 命名规则落地为 `${qmName}#${dimFieldBase}`。
- schema 规则落地为：
  - 根维度使用 canonical 字段：`id`、`caption`、TM 全属性
  - 嵌套子维度使用相对路径：`<relativePath>$id/$caption/$property`
  - 父子维节点支持 `parentId/depth/hasChildren`

## 关键设计取舍

- 解析入口仍以“根维度”为 synthetic member-QM 的归属单位；当 `fieldName` 命中嵌套子维度时，解析器返回对应根维度的 synthetic model。
- 嵌套维度匹配同时兼容：
  - 完整相对路径字段
  - QM 暴露的末端 alias 字段
- 父子维保留字段与 TM 属性重名时，不再直接报重复字段错误，而是对同名字段执行“保留字段提升”：
  - `parentId` 这类字段优先保留 hierarchy 语义
  - 同时保留其原始 sourceRef 回指能力
- 根维度的 hierarchy 保留字段 sourceRef 修正为 `rootBase$parentId/depth/hasChildren`，不再使用裸字段名。

## 遇到的问题与处理

- 问题：多级嵌套 alias 在原始 QM 中可被独立暴露，例如 `categoryGroup$groupType`，但初版解析器只接受完整相对路径。
  - 处理：补充“末端 effectiveName 匹配”规则。
- 问题：父子维的 `parentId` 与 TM 属性 `parent_id -> parentId` 重名。
  - 处理：为 reserved 字段增加提升逻辑，避免 schema 构建阶段直接冲突。
