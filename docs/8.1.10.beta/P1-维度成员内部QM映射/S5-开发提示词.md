# Stage5 开发提示词：缓存、热加载与文档收口

## 目标
- 验证 synthetic member-QM 在同一 namespace 下可复用缓存。
- 验证 `clearByNamespace`、bundle 移除、模型文件热变更后 synthetic member-QM 可失效并重建。
- 收口一份可供后续实现/联调复用的样例文档，覆盖普通维度、嵌套维度、父子维、external patch。

## 范围
- 不新增新的查询能力。
- 复用现有 `QueryModelLoader.clearByNamespace`、`BundleLifecycleListener`、`DbModelFileChangeHandler`。
- 样例文档只覆盖 `8.1.10.beta` MVP 已实现能力。

## 约束
- 所有验证结果必须落盘到：
  - `docs/8.1.10.beta/P1-维度成员内部QM映射/dev-logs/`
  - `docs/8.1.10.beta/P1-维度成员内部QM映射/test-records/`
- 至少给出一组：
  - 普通维度 simple 入口样例
  - 嵌套维度 DSL 样例
  - 父子维 hierarchy 样例
  - external patch 样例

## 验收标准
- 同一 namespace 下重复获取同一 synthetic member-QM，返回缓存实例。
- `clearByNamespace` 后 synthetic member-QM 可重新装载。
- `BundleRemovedEvent` 与 `FsscriptRemoveEvent` 后 synthetic member-QM 可重新装载。
- 文档明确说明：
  - simple 入口如何归一
  - DSL 入口如何直接命中 synthetic member-QM
  - external patch 的 extData 结构
  - 当前 MVP 不做的边界
