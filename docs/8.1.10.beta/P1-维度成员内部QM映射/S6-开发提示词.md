## 你需要做的事

### Step 1：配置定义

1. 在 `foggy-dataset-model` 的 `semantic/member/` 下新建 `permission/` 子包
2. 创建以下 Def 类：
   - `MemberPermissionDef`：patch（MemberPermissionPatchDef）+ queryBuilder（Object，FSScript 函数引用）
   - `MemberPermissionPatchDef`：visibleColumns（List<String>）/ forcedSlice（List<MemberPermissionSliceDef>）/ forcedOrderBy（List<OrderRequestDef>）/ hierarchyEnabled（Boolean）/ allowedHierarchyOps（List<String>）
   - `MemberPermissionSliceDef`：field / op / value（Object）/ valueBuilder（Object，FSScript 函数引用）
   - `QmMemberPermissionDef`：dimension（String）+ patch + queryBuilder
3. 在 `DbDimensionDef` 新增 `MemberPermissionDef memberPermission` 字段
4. 在 `DbQueryModelDef` 新增 `List<QmMemberPermissionDef> memberPermissions` 字段
5. 编译确认

### Step 2：FSScript loader 承载

1. 找到 TM loader 中处理 `dimensions[]` 的位置，增加对 `memberPermission` 的解析
2. 找到 QM loader 中处理顶层配置的位置，增加对 `memberPermissions[]` 的解析
3. `valueBuilder` 和 `queryBuilder` 在 loader 阶段保留为 FSScript 函数引用（Callable / ScriptFunction），不立即执行
4. 编写带 memberPermission 的 .tm/.qm 测试文件验证
5. 确认不带 memberPermission 的旧文件不受影响

### Step 3：权限合并器

1. 创建 `SyntheticMemberPermissionResolver`
2. 创建 `SyntheticMemberEffectivePermission`（合并结果）
3. 实现合并逻辑：
   - `visibleColumns`：QM 覆盖 TM（后者覆盖前者）
   - `forcedSlice`：同字段 QM 完全替换 TM，不同字段合并保留
   - `forcedOrderBy`：同字段 QM 覆盖 TM
   - `hierarchyEnabled` / `allowedHierarchyOps`：QM 覆盖 TM
   - `queryBuilder`：TM 和 QM 都保留，按 TM→QM 顺序收集为列表
4. 单元测试覆盖全部合并场景

### Step 4：内部 patch 注入

1. 创建 `SyntheticMemberInternalPatchStep implements DataSetResultStep`
2. **`@Order(-20)`** — 在 external patch（-10）之前执行
3. beforeQuery 流程：
   a. 检测 queryModel 名称是否包含 `#`（同 external patch 的判断方式）
   b. 从 sourceModel 对应的 TM + QM 获取权限配置
   c. 调用 `SyntheticMemberPermissionResolver` 合并
   d. 对 `forcedSlice` 中有 `valueBuilder` 的项执行求值
   e. 将结果写入 queryRequest（参考 external patch 的 merge 方式）
4. 参考 `SyntheticMemberExternalPatchStep` 的 mergeColumns/mergeSlice/mergeOrderBy 复用或抽取公共方法
5. 测试：内部 patch → external patch → request 的叠加优先级

### Step 5：queryBuilder 执行

1. 创建 `SyntheticMemberQueryBuilderStep`
2. 参考现有 `accesses[].queryBuilder` 的执行方式
3. 构建 context 对象：
   ```
   context.query      → JdbcQuery 操作代理
   context.member     → synthetic member-QM 字段空间代理
   context.queryModel → 当前 queryModel
   context.request    → 当前 request
   context.security   → 安全上下文
   context.extData    → 扩展数据
   context.namespace  → 命名空间
   ```
4. 按 TM→QM 顺序执行 queryBuilder 列表
5. 测试：queryBuilder 追加 where 条件后 SQL 正确

### Step 6：集成测试与文档

1. 编写端到端测试：
   - 仅 TM 权限
   - 仅 QM 权限
   - TM+QM 合并 + external patch 叠加
   - valueBuilder 动态求值
   - queryBuilder SQL 注入
   - hierarchyEnabled=false 拦截
2. 运行全部测试确认通过
3. 写 dev-log 到 `docs/8.1.10.beta/P1-维度成员内部QM映射/dev-logs/S6-{YYYYMMDD}-内部成员权限.md`
4. 写 test-record 到 `docs/8.1.10.beta/P1-维度成员内部QM映射/test-records/T6-{YYYYMMDD}-内部成员权限.md`

## 你不需要做的事

- 不改动 `SyntheticMemberQueryModelResolver`（schema 解析器）
- 不改动 `SyntheticMemberQueryModelFactory`（运行时工厂）
- 不做运行时沙箱校验（queryBuilder 安全依赖开发者自律）
- 不设计前端契约
- 不处理 context permission 或事实数据上下文裁剪
- 不做混合模式（CONTEXT_DISTINCT / HYBRID）

## 验收方式

```bash
# 编译
mvn compile -pl foggy-dataset-model -DskipTests

# 单元测试（SQLite，无需 Docker）
mvn test -pl foggy-dataset-model -Dspring.profiles.active=sqlite

# 如有多数据库测试需求
mvn test -pl foggy-dataset-model -Dspring.profiles.active=docker
```

检查项：
- [ ] 编译零错误
- [ ] 所有测试通过（包括新增的权限合并、patch 注入、queryBuilder 测试）
- [ ] 旧有 synthetic member-QM 测试不回归
- [ ] 不含 memberPermission 的 .tm/.qm 文件解析不受影响
- [ ] dev-log 和 test-record 已写入

2. **测试全部通过**：`mvn test` 无失败用例，不允许跳过失败测试
3. **如外部环境不可用**：在 progress 中标注"测试未运行"及原因，不得标记完成
4. **dev-log 已写入**
5. **test-record 已写入**
