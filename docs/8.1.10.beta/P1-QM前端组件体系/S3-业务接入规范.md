# S3 - 业务接入规范

## 基本信息
- 优先级：**P1**（依赖 S1 字段结构 + S2 组件接口稳定后落地）
- 状态：`已锁定`

## 目标
定义业务系统如何接入生成产物——使"能生成"变成"能稳定使用"。

## 核心原则
1. **不改 generated 文件** — 生成产物只由生成器覆盖，业务改动放在包装层
2. **薄组件 + 厚包装** — 生成组件只做 schema 组装，业务逻辑在包装层
3. **参数显式分层** — globalParams 和 customParams 不混用

## 三层目录结构

```
src/
  generated/                    # 生成器自动输出，禁止手改
    qm/
      order/
        FactOrder.types.ts
        FactOrder.table.schema.ts
        FactOrder.query.schema.ts
        FactOrder.api.ts
        FactOrderTable.vue
        index.ts
  modules/                      # 业务包装层（手工维护）
    order/
      OrderListModule.vue       # 组合 generated 组件 + 业务插槽
      order-module.config.ts    # 列覆盖、默认参数、动作声明
      order-query-hooks.ts      # 查询前后处理、埋点、错误处理
  pages/                        # 页面层（手工维护）
    order/
      OrderListPage.vue         # 布局、路由、组合多个 Module
```

**约束**：
- `generated/` 只允许覆盖式重生成
- 人工定制不得修改 generated 文件；如需变更，调整模板、参数或扩展文件
- 不鼓励页面直接消费 generated 组件（PoC 除外）

## 参数合并规则

### globalParams
合并顺序（后者覆盖前者同名 key）：
1. 宿主层基础全局参数（如 tenantId、namespace）
2. 业务模块默认全局参数
3. 页面传入 `globalParams`
4. `beforeQuery` hook 最终 patch

规则：
- 普通对象浅合并
- 数组直接替换
- 安全上下文字段（租户、权限、namespace）不允许页面层覆盖

### customParams
合并顺序：
1. 生成组件默认 custom 参数
2. 业务模块默认 custom 参数
3. 页面传入 `customParams`
4. `beforeQuery` hook 最终 patch

规则：
- 普通对象浅合并
- 数组替换
- 仅承载模型或页面专属参数

### initialSlices
- 生成组件若有默认 slices，作为 base
- 页面传入的 `initialSlices` 按 `field + op` 维度覆盖同类条件
- 无法判定等价关系的 slice 直接追加
- 不做隐式深合并

## 列覆盖规则

### 原则
- 按 `column.name`（即 `fieldName`）为主键覆盖
- 不按数组下标覆盖
- 不要求复制整份 schema

### 合并顺序
1. generated schema 列定义
2. 业务模块默认列覆盖（`order-module.config.ts`）
3. 页面传入 `columnOverrides`

### 字段级规则
```ts
interface BusinessColumnOverride {
  title?: string          // 覆盖显示名
  width?: number | string // 覆盖列宽
  hidden?: boolean        // 隐藏（schema 保留，UI 不渲染）
  order?: number          // 展示排序（不回写 generated）
  formatter?: (value: unknown) => string
  uiConfig?: Record<string, unknown>  // 浅合并
}
```

- 标量字段：后者覆盖前者
- `uiConfig`：浅合并
- `hidden = true`：不展示，但原始 schema 仍保留
- `order`：仅影响最终展示排序

### 新增业务列
通过包装层追加，不修改 generated schema：
- 附加列默认追加到末尾
- 指定 `order` 参与排序
- 应显式标识为业务列

## Query Schema 覆盖规则

包装层可覆盖：
- `placement`
- `order` / `span` / `visible`
- `layout`（查询区布局）
- 追加 `hidden` 条件

不应破坏：
- `sourceField` 的值字段归一规则
- lookup/member 类型到值字段的映射
- draft/applied 统一状态模型

## 包装层 API

### 生成组件暴露的 Props
```ts
interface GeneratedTableProps {
  globalParams?: Record<string, unknown>
  customParams?: Record<string, unknown>
  initialSlices?: SliceRequestDef[]
  tableOverrides?: Partial<TableConfig>
  columnOverrides?: Record<string, BusinessColumnOverride>
  queryOverrides?: Partial<QuerySchema>
  queryHooks?: QueryHooks
  lookupAdapters?: Record<string, MemberLookupAdapter>
}
```

### 包装层对页面暴露的 Props
```ts
interface OrderListModuleProps {
  globalParams?: Record<string, unknown>
  customParams?: Record<string, unknown>
  initialSlices?: SliceRequestDef[]
  tableOverrides?: Partial<TableConfig>
  columnOverrides?: Record<string, BusinessColumnOverride>
  queryHooks?: QueryHooks
}
```

页面层只传"业务意图"，包装层内部适配成生成组件可识别的输入。

### 包装层文件拆分
每个业务模块建议拆为：
- `XxxListModule.vue` — 组合 generated 组件和业务插槽
- `xxx-module.config.ts` — 静态列覆盖、默认参数、动作声明
- `xxx-query-hooks.ts` — 查询前后处理、埋点、错误处理

## 扩展点清单

生成组件必须预留（`8.1.10.beta` 最小集）：

| 扩展点 | 类型 | 说明 |
|--------|------|------|
| `toolbar` | slot | 工具栏按钮区 |
| `row-actions` | slot | 行级操作按钮 |
| `columnOverrides` | prop | 列配置覆盖 |
| `queryOverrides` | prop | 查询条件覆盖 |
| `globalParams` | prop | 全局参数注入 |
| `customParams` | prop | 模型级定制参数 |
| `queryHooks` | prop | 查询生命周期钩子 |
| `qmModel` | prop | 透传给远程 lookup |
| `lookupAdapters` | prop | 远程 lookup adapter 注入 |

## tableOverrides 规则
用于表格级轻量覆盖：
- 分页大小
- 默认高度
- 是否显示工具栏

规则：
- 只做浅合并
- 不承载列级覆盖
- 不承载业务权限逻辑

## 反模式（禁止）

| 做法 | 问题 |
|------|------|
| 页面直接复制 generated schema 数组后修改 | 模型迭代后失控 |
| 基于数组下标做列覆盖 | 字段增删后错位 |
| 多个页面各自维护几乎相同的 schema 副本 | 重复、漂移 |
| 页面直接改 generated 文件 | 下次生成被覆盖 |
| 在 generated 组件里写业务弹窗/权限逻辑 | 模板失控 |
| 在页面散用底层 schema 和 API | 绕过标准层 |

## 验收标准
- [ ] 至少一个业务模块（如订单列表）完成三层接入
- [ ] generated 文件可重新生成而不影响业务包装层
- [ ] 列覆盖按 name 生效，不依赖数组下标
- [ ] globalParams 和 customParams 合并顺序正确
- [ ] 包装层 hooks 正常拦截/修改查询
