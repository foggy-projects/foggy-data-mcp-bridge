# S2 - 标准组件规范

## 基本信息
- 优先级：**P0**（与 S1 并行，维度成员过滤已有内部能力可直接接入）
- 状态：`已锁定`

## 目标
定义 `foggy-data-viewer` 需要新增和升级的标准组件接口，让业务系统在表格、查询、下拉场景中有统一的消费入口。

## 模块 A：维度成员实时过滤（P0）

### 服务端接口

```
POST /data-viewer/api/members/query
```

#### 请求体
```ts
interface MemberQueryRequest {
  qmModel: string              // 必填，业务 QM 名称
  fieldName: string            // 必填，schema 暴露的字段名（如 team$caption）
  keyword?: string             // 搜索关键字
  start?: number               // 默认 0
  limit?: number               // 默认 20
  selectedValues?: Array<string | number>  // 回填已选值
  hierarchy?: {
    op: string                 // 本版本只正式支持 childrenOf
    value: string | number
  }
}
```

#### 响应体
```ts
interface MemberQueryResponse {
  qmModel?: string
  fieldName?: string
  selectionFieldName: string   // 前端生成 DSL slice 必须使用此字段
  displayFieldName: string
  hierarchical?: boolean
  hierarchyOps?: string[]      // 本版本前端只消费 childrenOf
  items: MemberOption[]
  selectedItems?: MemberOption[]
  total: number
  hasMore?: boolean
}

interface MemberOption {
  value: string | number
  label: string
  parentValue?: string | number | null
  depth?: number
  hasChildren?: boolean
  pathValues?: Array<string | number>   // 可选扩展
  pathLabels?: string[]                 // 可选扩展
  disabled?: boolean                    // 可选扩展
}
```

#### selectionFieldName 映射规则
- `team$caption` → `selectionFieldName: "team$id"`
- `customer$caption` → `selectionFieldName: "customer$id"`
- 无法推导成对的字段 → 不启用维度成员过滤

**核心约束**：前端生成 DSL `slice` 时，`field` 必须使用 `selectionFieldName`，不能使用 `displayFieldName`。

### 前端类型扩展

在 `types/index.ts` 新增：

```ts
export interface MemberLookupMeta {
  enabled: boolean
  selectionFieldName: string
  displayFieldName: string
  searchable?: boolean
  pageable?: boolean
  defaultLimit?: number
}
```

在 `ColumnSchema` 上新增：

```ts
export interface ColumnSchema {
  // ...已有字段
  hierarchical?: boolean
  hierarchyOps?: string[]
  memberLookup?: MemberLookupMeta
}
```

### 前端 API 新增

```ts
// viewer.ts
export async function fetchMemberOptions(
  request: MemberQueryRequest
): Promise<MemberQueryResponse> {
  const res = await axios.post('/data-viewer/api/members/query', request)
  return res.data.data
}
```

### 组件改造

#### SearchToolbar
新增远程成员加载入口：
```ts
props: {
  // 已有
  filterOptionsLoader?: (columnName: string) => Promise<FilterOption[]>
  // 新增
  filterMemberLoader?: (request: MemberQueryRequest) => Promise<MemberQueryResponse>
}
```
当列包含 `memberLookup` 时，优先走 `filterMemberLoader`。

#### SelectFilter 升级
支持三种模式：
1. **静态 options** — 现有行为不变
2. **远程 member** — keyword debounce → 远程搜索 → 分页 → selectedValues 回填
3. **树形 member** — 消费 `parentValue/depth/hasChildren`，基于 `vxe-table` 树能力

远程 member 模式行为：
- 打开下拉 → 首次加载（`keyword=''`）
- 输入关键词 → 250ms debounce → 远程搜索
- 单选 → 立即产出 `[{ field: selectionFieldName, op: '=', value }]`
- 多选 → 确认后产出 `[{ field: selectionFieldName, op: 'in', value: [...] }]`
- 清空 → 返回 `null`

#### DataTableWithSearch
需保证 `qmModel` 能传到 SearchToolbar：
- schema 模式：从 `tableConfig.qmModel` 或外层 props 读取
- 未提供 `qmModel` 时，dimension 远程过滤不自动启用

### 服务端适配
`data-viewer` 服务端 adapter 职责：
1. 接收 `qmModel + fieldName + 查询参数`
2. 映射到内部 synthetic member-QM
3. 调用既有 simple/direct DSL
4. 归一化成 `MemberQueryResponse`
5. 保持 header / namespace / 鉴权上下文

**约束**：不暴露 synthetic member-QM 名称、不暴露 `/jdbc-model/...` URL。

### 实施顺序
1. `types/index.ts` 补齐类型
2. `viewer.ts` 新增 `fetchMemberOptions`
3. 服务端 `members/query` adapter
4. `SearchToolbar` 改造
5. `SelectFilter` 升级
6. `DataTableWithSearch` 打通 `qmModel` 透传

## 模块 B：查询条件区与列筛选并存（P1）

### 核心模型

#### QueryFieldSchema
```ts
interface QueryFieldSchema {
  key: string                    // 查询条件唯一键
  label: string                  // 显示名称
  sourceField?: string           // 生成 slice 使用的字段（值字段）
  placement: 'form' | 'column' | 'hidden'  // 出现位置
  component:
    | 'text' | 'numberRange' | 'dateRange'
    | 'dictSelect' | 'qmLookupSelect' | 'memberSelect'
    | 'bool' | 'custom'
  defaultOperator?: string
  defaultValue?: unknown
  columnRef?: string             // 关联的展示列名
  dictId?: string
  lookupRef?: string
  order?: number
  span?: number                  // grid 单元数
  visible?: boolean
}
```

#### QuerySchema
```ts
interface QuerySchema {
  fields: QueryFieldSchema[]
  submitMode: 'manual'           // 8.1.10.beta 固定为 manual
  collapsible?: boolean          // 默认 true
  defaultExpanded?: boolean      // 默认 true
  layout?: QueryPanelLayoutSchema
}

interface QueryPanelLayoutSchema {
  mode: 'grid'                   // 8.1.10.beta 固定为 grid
  columns?: { xs?: 1; sm?: 2; md?: 3; lg?: 4; xl?: 4 }
  labelWidth?: number
  actionAlign?: 'left' | 'right' // 默认 right
  collapsedRows?: number         // 默认 1
  gutter?: number
}
```

### placement 规则

| 值 | 含义 | 适用场景 |
|----|------|---------|
| `form` | 只出现在表格上方查询区 | 复杂条件、日期范围、远程 lookup |
| `column` | 只出现在快捷列筛选区 | 高频轻量筛选 |
| `hidden` | 不展示，只作为默认/注入条件 | 租户、权限约束 |

> **说明**：讨论稿中的 `both` 模式（同时出现在查询区和列筛选）在本版本暂不实现。原因：`both` 引入的双向状态同步复杂度较高，先验证 `form` + `column` 独立运行后再叠加联动。

### 统一状态模型

```ts
// 建议由 foggy-data-viewer 提供 composable
function useQueryState(): {
  draft: Ref<Record<string, unknown>>     // 用户输入中的草稿
  applied: Ref<Record<string, unknown>>   // 已提交的有效条件
  commitDraft(): void                     // draft → applied，触发服务端查询
  resetAll(): void                        // 清空 draft + applied
  patchDraft(field: string, value: unknown): void
}
```

- QueryPanel 和 ColumnFilters 读写同一份 `draft`
- 显式触发"查询/回车"后，`draft` 提交为 `applied`
- 服务端查询始终基于 `applied`
- 本地预览过滤可基于 `draft`（仅列筛选，查询区不触发）

### 提交规则
- **查询区**：点击"查询"按钮 → `commitDraft()` → 服务端查询
- **列筛选文本**：回车 → `commitDraft()` → 服务端查询
- **列筛选下拉**：确认/查询按钮 → `commitDraft()` → 服务端查询
- 任何场景都不允许输入即自动触发服务端查询

### sourceField 归一规则
查询条件最终落到"值字段"：
- 字典字段 → 使用业务值字段
- member/lookup → 使用 `$id` 字段
- `team$caption` 在查询层归一到 `team$id`
- `statusLabel` 若仅展示标签，不作为默认 sourceField

### 组件要求

#### QueryPanel（新增）
- 根据 `QuerySchema` 渲染传统查询区
- 支持折叠/展开
- 支持查询/重置操作区

#### DataTableWithSearch 扩展
```ts
props: {
  // 新增
  querySchema?: QuerySchema
  showQueryPanel?: boolean      // 默认 false
  showColumnFilters?: boolean   // 默认 true（保持现有行为）
}
```

### 组件默认占位
| component | 默认 span |
|-----------|----------|
| `text` / `bool` / `dictSelect` | 1 |
| `memberSelect` / `qmLookupSelect` | 1 |
| `numberRange` / `dateRange` | 2 |
| `custom` | 2 |

## 模块 C：下拉组件契约（P1）

### 字典下拉

锚点：`dictId`

本版本策略：**优先静态快照**
- 生成器在开发期拉取字典数据 → 生成 `*.options.ts`
- 组件默认消费本地 options
- `dictMode = 'remote'` 时通过 adapter 注入远程加载

生成产物示例：
```
generated/qm/order/OrderStatusSelect.vue
generated/qm/order/order-status.options.ts
```

### QM 查询下拉（维度成员 Lookup）

锚点：`qmModel + memberLookup`

本版本统一使用模块 A 的 `MemberQueryRequest/Response` 协议，不再单独定义 `QmLookupConfig`。

组件生成产物示例：
```
generated/qm/order/CustomerLookupSelect.vue
```

内部调用 `fetchMemberOptions(request)`。

### 与表格的关系
- 表格组件：面向列表展示和筛选
- 下拉组件：面向表单输入、筛选输入、引用选择
- 两者共享：lookup 协议、query hooks、globalParams / customParams
