# S4 - 代码生成器规范

## 基本信息
- 优先级：**P2**（依赖 S1+S2+S3 全部稳定）
- 状态：`已锁定`

## 目标
定义前端代码生成器的输入、输出、模板职责和运行流程，使 QM 模型变更后前端可一键重生成标准代码。

## 生成器定位
- **输入**：`frontend-meta v1` JSON（来自后端接口或离线快照）
- **输出**：TypeScript + Vue 3 代码文件
- **不做**：生成完整业务页面、生成包装层、生成路由配置

## 生成产物

以 `FactOrderQueryModel` 为例：

```
generated/qm/order/
  FactOrder.types.ts           # 行类型、查询参数类型
  FactOrder.table.schema.ts    # TableSchema 配置
  FactOrder.query.schema.ts    # QuerySchema 配置
  FactOrder.api.ts             # 查询 API 薄封装
  FactOrderTable.vue           # 基于 DataTableWithSearch 的薄组件
  index.ts                     # 统一导出
```

### 文件职责

| 文件 | 职责 | 不做 |
|------|------|------|
| `types.ts` | QM 行类型、查询参数类型、可复用字典类型 | 不定义业务弹窗/表单类型 |
| `table.schema.ts` | `EnhancedColumnSchema[]`、默认 `visibleColumns`、`pageSize` | 不含查询条件布局 |
| `query.schema.ts` | `QueryFieldSchema[]`、查询区 `layout`、`placement` 默认值 | 不含列展示配置 |
| `api.ts` | 调用 `fetchQueryData` / `fetchMemberOptions` 的薄封装 | 不含业务鉴权/埋点 |
| `Table.vue` | 组装 `DataTableWithSearch` + schema + api | 不含工具栏按钮/业务弹窗 |
| `index.ts` | re-export 所有生成产物 | — |

## 生成规则

### types.ts 生成

从 `frontend-meta v1` 的 `fields` 数组推导：

```ts
// 行类型
export interface FactOrderRow {
  'orderDate$id'?: string
  'orderDate$caption'?: string
  'customer$id'?: string
  'customer$caption'?: string
  'orderId'?: string
  'orderStatus'?: string
  'quantity'?: number
  'amount'?: number
  // ...
}
```

类型映射：
| FieldMeta.type | TypeScript |
|----------------|-----------|
| `TEXT` `STRING` | `string` |
| `INTEGER` | `number` |
| `BIGINT` | `number` |
| `NUMBER` `MONEY` | `number` |
| `DAY` `DATETIME` | `string` |
| `BOOL` | `boolean` |

### table.schema.ts 生成

从 `fields` + `defaults` 推导 `EnhancedColumnSchema[]`：
- `name` ← `FieldMeta.name`
- `title` ← `FieldMeta.title`
- `type` ← `FieldMeta.type`
- `filterType` ← `FieldMeta.filterType`
- `filterable` ← `FieldMeta.filterable`
- `measure` ← `FieldMeta.measure`
- `aggregatable` ← `FieldMeta.aggregatable`
- `dictId` ← `FieldMeta.dictId`
- `memberLookup` ← `FieldMeta.memberLookup`
- `width` ← `FieldMeta.uiHints?.width` 或 `calculateColumnWidth(title, type)`

`defaults.visibleColumns` 决定列顺序和可见性。

### query.schema.ts 生成

#### 字段纳入规则
默认只纳入满足以下条件的字段：
- `filterable = true`
- 不是 `dimension-id` 类别（过滤器挂在 `$caption` 上）
- 不是纯展示型 `calculated` 字段
- 不是仅用于展示的冗余 caption

默认排除：
- `measure = true` 且无明确筛选语义的聚合指标
- `category = 'dimension-id'`（由对应 `$caption` 字段代理）

#### 组件类型映射
| 条件 | 生成 component |
|------|---------------|
| 有 `dictId` | `dictSelect` |
| `filterType = 'dimension'` 且有 `memberLookup` | `memberSelect` |
| `filterType = 'date'` 或 `'datetime'` | `dateRange` |
| `filterType = 'number'` | `numberRange` |
| `filterType = 'bool'` | `bool` |
| 其他可搜索文本 | `text` |

#### placement 默认映射
| component | 默认 placement |
|-----------|---------------|
| `text`（高频关键词） | `column` |
| `dictSelect` / `bool` | `column` |
| `dateRange` / `numberRange` | `form` |
| `memberSelect` | `form` |

#### sourceField 归一
- `customer$caption` → `sourceField: 'customer$id'`（通过 `memberLookup.selectionFieldName`）
- `orderStatus`（dictId） → `sourceField: 'orderStatus'`
- 普通 text → `sourceField` = 字段自身

#### 字段排序
若后端未提供顺序，按以下规则推导：
1. 关键词类字段
2. 高频状态/枚举字段
3. 时间范围字段
4. 维度/lookup 字段
5. 其他低频条件

### api.ts 生成

```ts
import { fetchQueryData, fetchMemberOptions } from 'foggy-data-viewer'
import type { FetchDataParams, FetchDataResult, MemberQueryRequest } from 'foggy-data-viewer'
import type { FactOrderRow } from './FactOrder.types'

const QM_MODEL = 'FactOrderQueryModel'

export async function queryOrders(params: FetchDataParams): Promise<FetchDataResult<FactOrderRow>> {
  return fetchQueryData(QM_MODEL, params)
}

export async function queryOrderMembers(request: Omit<MemberQueryRequest, 'qmModel'>) {
  return fetchMemberOptions({ ...request, qmModel: QM_MODEL })
}
```

### Table.vue 生成

```vue
<template>
  <DataTableWithSearch
    :schema="mergedSchema"
    :fetch-data="queryOrders"
    :query-schema="querySchema"
    :show-query-panel="showQueryPanel"
    v-bind="$attrs"
  >
    <template v-if="$slots.toolbar" #toolbar>
      <slot name="toolbar" />
    </template>
    <template v-if="$slots['row-actions']" #row-actions="scope">
      <slot name="row-actions" v-bind="scope" />
    </template>
  </DataTableWithSearch>
</template>
```

Props 暴露：`globalParams`、`customParams`、`initialSlices`、`columnOverrides`、`queryOverrides`、`queryHooks`、`showQueryPanel`。

## 生成流程

### 开发态
```bash
# 单模型生成
npx foggy-gen --model FactOrderQueryModel --output src/generated/qm/order

# 批量生成
npx foggy-gen --all --output src/generated/qm

# 从离线快照生成
npx foggy-gen --file ./meta-snapshot/FactOrder.frontend-meta.json --output src/generated/qm/order
```

### CI 态
```bash
# 1. 从后端拉取最新元数据快照
npx foggy-gen snapshot --output ./meta-snapshot

# 2. 基于快照生成代码
npx foggy-gen --all --from-snapshot ./meta-snapshot --output src/generated/qm

# 3. 校验是否有未提交变更
git diff --exit-code src/generated/
```

## 防覆盖规则
- 生成器只写入 `generated/` 目录
- 每次生成为全量覆盖，不做增量合并
- 业务代码在 `modules/` 和 `pages/` 中，不受影响
- 若生成结果与上次相同，不触发文件写入（避免无意义 git diff）

## 生成器落地形态
本版本推荐 **CLI 工具**（`npx foggy-gen`）。

后续可扩展为：
- Vite 插件（自动 watch 元数据变更 → 重生成）
- monorepo 工具集成
