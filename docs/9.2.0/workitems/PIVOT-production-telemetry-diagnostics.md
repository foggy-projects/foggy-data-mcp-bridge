# Pivot Production Telemetry Diagnostics

## Scope

`PIVOT-92-O1` previously had safe log markers, but response-level evidence was not standardized. That made AI/debug consumers and operational tooling depend on log parsing to understand whether a Pivot query used SQL pushdown, axis-domain selection, cascade generation, or large-domain transport.

This work keeps the Pivot DSL and execution behavior unchanged. It adds a compact diagnostics contract to successful Pivot responses and fills one missing log marker for cascade refusals.

## Implementation

- Added a response diagnostics collector in the Pivot pipeline.
- Exposed successful Pivot execution diagnostics at `SemanticQueryResponse.debug.extra.pivotDiagnostics`.
- Recorded SQL pushdown attempted/succeeded/fallback/skipped decisions.
- Recorded axis-domain selection entry and large-domain transport plan summaries.
- Recorded final execution-path summary with `sqlPushdownUsed`, `axisDomainSelectionUsed`, `cascadeGenerateUsed`, `memoryShapingUsed`, `resultRows`, `rowDomainSize`, and `columnDomainSize`.
- Added `pivot.cascade.refused` log marker before cascade fail-closed exceptions.
- Added `pivot.domain_transport.planned` logging for axis-domain transport plans generated by Pivot before JDBC applies or refuses them.

## Response Contract

`debug.extra.pivotDiagnostics` is a list of maps. Each item includes:

- `event`: stable event name such as `pivot.sql_pushdown.skipped`, `pivot.axis_domain_selection.started`, `pivot.domain_transport.planned`, or `pivot.execution_path`.
- `decision`: compact decision value such as `skipped`, `started`, `planned`, or `completed`.
- `model`: query model name.
- Optional event-specific fields such as `reason`, `reasonClass`, `relation`, `fieldCount`, `tupleCount`, `parameterCount`, `resultRows`, `rowDomainSize`, and `columnDomainSize`.

The contract intentionally does not record concrete axis member values.

## Remaining Boundary

- This is not a full operational dashboard. It standardizes the runtime evidence payload and log marker surface that dashboards or log queries can consume.
- Cascade refusal responses still fail closed through exceptions; refusal rate should be measured through `pivot.cascade.refused` logs unless a future controller-level error envelope exposes structured exception metadata.
- Dialect-specific transport applied/refused evidence remains in JDBC engine logs; Pivot response diagnostics records the generated plan, not the final database renderer outcome.
