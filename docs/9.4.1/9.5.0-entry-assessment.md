# 9.5.0 Legacy Exit Entry Assessment

## 1. Remaining legacy surface

- direct `foggy-dataset-model` dependencies: **14**;
- production old-package imports outside aggregate: **11 modules / 110 files**;
- approved direct `model.query()` bypass: **1** (`DatasetClientProxy`);
- unapproved bypass: **0**.

## 2. Physical relocation still required

- loader/catalog: MCP and Mongo model loaders, lifecycle and catalog publication need stable load roles and ownership;
- engine: Mongo/vector/cache/preagg execution implementations must move behind adapter-owned contracts;
- semantic: runtime, MCP and memory-grid planning/execution/metadata types need physical port/DTO boundaries;
- pivot/compose: pivot planning/result and compose execution types still cross legacy module boundaries;
- compatibility assembly: launcher, benchmark, viewer and public GraphQL converter still consume legacy types or aggregate.

## 3. Provider/TCK coverage

| Contract | Coverage |
|---|---|
| model query | JDBC provider/TCK covered |
| model load | not covered / not adopted |
| namespace isolation | no independent provider/TCK contract |
| atomic refresh | not covered / not adopted |
| cache invalidation | query-cache provider/TCK/context covered |
| error contract | duplicate, missing, unsupported and role mismatch covered in catalog |

## 4. Compatibility bridge removal readiness

Not yet. One compatibility cycle has elapsed, but elapsed time alone is insufficient while 14 direct dependencies,
110 imports, a public legacy converter, runtime/semantic/engine type crossings and the client bypass remain. Removal
requires an external-consumer migration window and a frozen physical split.

## 5. Expected 9.5.0 breaking changes

- removing the aggregate's transitive module supply and requiring explicit replacement dependencies;
- deleting deprecated facade adapters, advanced methods, constructors or legacy SPI;
- moving loader/engine/semantic/pivot/compose packages or changing their ownership;
- replacing direct model/load/query lifecycle contracts with provider/port DTOs;
- making provider capability/role requirements mandatory for additional capabilities;
- possible source and binary incompatibility for external consumers compiled against legacy types.

Each item requires explicit API/SPI breaking authorization and a migration/rollback contract before implementation.

## 6. Full release-governance authority recommendation

Recommended before legacy exit. Decision value is high: it is the only planned evidence that can test the complete
artifact/dependency graph, external compatibility assumptions, semantic/portable replay, source sealing and governed
database/runtime lanes after bridge removal.

- lean authority without generic five-DB breadth: estimated **60–120 minutes** when fixtures are available;
- authority including semantic/portable replay and a full database matrix: budget **2–4 hours**, plus external fixture
  startup or infrastructure delay;
- run timing: after the 9.5.0 breaking plan and candidate are frozen, before tag/release/publish.

## Final Evaluation

`READY_WITH_PREREQUISITES`

Prerequisites: freeze the physical split, define truthful load/namespace/atomic-refresh contracts, remove the approved
bypass, publish external migration and breaking-change contracts, obtain explicit owner authorization, and approve the
final release-governance authority budget. This assessment does not authorize or start 9.5.0 implementation.
