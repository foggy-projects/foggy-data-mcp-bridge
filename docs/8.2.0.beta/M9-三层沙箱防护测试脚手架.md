# M9 · 三层沙箱防护测试脚手架

## 文档作用

- doc_type: test-scaffold-blueprint
- intended_for: execution-agent / reviewer
- purpose: 为 `P0-ComposeQuery-沙箱白名单错误码与防护用例清单.md` 中的 24 条用例提供 Java / Python 双仓可直接落地的测试脚手架，确保实现方拿到本文档即可 1:1 翻译成真实测试代码

## 为什么先落脚手架而不是真实测试代码

- M9 真实测试依赖 M1-M7 的类型与运行时（`ComposeQueryContext / QueryPlan / ScriptQueryTool / ComposeSandboxViolationException`）
- 在 M2/M3 完成前写真实代码会 fail-compile / fail-import，污染 CI
- 脚手架以 Markdown 承载，实现方拿来后按章节 1:1 粘贴到 `.java` / `.py` 文件即可，不产生构建风险

## 落地目标

实施方完成以下动作即视为 M9 完成：

1. 在 Java 仓新建 `SandboxLayerATest.java` / `SandboxLayerBTest.java` / `SandboxLayerCTest.java`，每条用例 ID 对应一个 `@Test` 方法
2. 在 Python 仓新建 `test_sandbox_layer_a.py` / `test_sandbox_layer_b.py` / `test_sandbox_layer_c.py`，每条用例 ID 对应一个测试函数
3. 每个测试方法/函数的名称、断言结构、错误码字符串严格遵循本脚手架
4. Java / Python 两仓同名用例 ID 断言的错误码字符串**完全一致**

### 统一断言工具

```java
// ComposeSandboxTestSupport.java
protected static void assertSandboxViolation(
        Runnable action, String expectedCode, String expectedLayer, String expectedKind) {
    ComposeSandboxViolationException ex = assertThrows(ComposeSandboxViolationException.class, action::run);
    assertEquals(expectedCode, ex.code());
    assertEquals(expectedLayer, ex.layer());
    assertEquals(expectedKind, ex.kind());
    assertTrue(
        Set.of("script-parse", "script-eval", "plan-build", "schema-derive",
               "authority-resolve", "compile", "execute").contains(ex.phase()),
        "phase must be in enum: " + ex.phase());
}
```

```python
# compose_sandbox_test_support.py
def assert_sandbox_violation(callable_, expected_code, expected_layer, expected_kind):
    with pytest.raises(ComposeSandboxViolationError) as exc_info:
        callable_()
    err = exc_info.value
    assert err.code == expected_code
    assert err.layer == expected_layer
    assert err.kind == expected_kind
    assert err.phase in {"script-parse", "script-eval", "plan-build", "schema-derive",
                        "authority-resolve", "compile", "execute"}
```

### A-03 `async-fetch`

**Java / Python**：script = `await fetch('http://evil.example/')`；预期抛 `LAYER_A_ASYNC_DENIED` 或 `LAYER_A_NETWORK_DENIED` 之一。

断言方式改为双候选：

```java
@Test
void a03_asyncFetchShouldBeDenied() {
    String script = "await fetch('http://evil.example/')";
    ComposeSandboxViolationException ex = assertThrows(
        ComposeSandboxViolationException.class, () -> newRunner().run(script));
    assertTrue(
        Set.of(SandboxErrorCodes.LAYER_A_ASYNC_DENIED, SandboxErrorCodes.LAYER_A_NETWORK_DENIED)
            .contains(ex.code()),
        "A-03 must trigger either async-denied or network-denied, got: " + ex.code());
    assertEquals("A", ex.layer());
}
```

Python 对等用 `pytest.raises` + 手动校验 `err.code in {...}`。

### B-02 `blocked-function-sleep`

### B-03 `injection-union-select`

slice = `[{field:'name', op:'=', value:"a' UNION SELECT ..."}]`

预期：**接受 `LAYER_B_INJECTION_SUSPECTED`** 或**被参数化安全处理**（不抛错，但执行时 SQL 是参数化 prepared statement，不拼接）。两种都合法，断言为：

```java
@Test
void b03_unionSelectInjectionShouldBeNeutralized() {
    String script = "from({model:'X', slice:[{field:'name', op:'=', value:\"a' UNION SELECT 1,2,3--\"}]})";
    try {
        String sql = newRunner().runToSql(script);
        // 参数化路径：SQL 必须使用 ? 占位符，原始字符串不得出现在 SQL 文本中
        assertFalse(sql.contains("UNION SELECT"), "Raw injection payload leaked into SQL: " + sql);
    } catch (ComposeSandboxViolationException ex) {
        // 拦截路径：错误码必须是 injection-suspected
        assertEquals(SandboxErrorCodes.LAYER_B_INJECTION_SUSPECTED, ex.code());
    }
}
```

### B-04 `derived-raw-sql`

script（派生层调用假想 `RAW_SQL` 函数）：

```js

base.query({columns:['RAW_SQL("DROP TABLE x")']});
```

预期：`LAYER_B_DERIVED_FN_DENIED`（如果 `RAW_SQL` 未实装，`LAYER_B_FUNCTION_DENIED` 也合法；断言用 oneOf）。

### B-06 `allowed-iif-sum` · **合法用例**

### C-05 `cross-datasource-join`

```js

a.join(b, { type:'left', on: [{left:'id', op:'=', right:'id'}] });
```

### C-06 `legal-chain` · **合法用例**

```js
return merged.query({columns:['id','SUM(val) as total'], groupBy:['id']}).execute();
```

→ 不抛错。

## 两仓 parity 守护

在两仓 CI 中（或至少 M9 验收阶段）各跑一次：

```bash
# Java
mvn test -pl foggy-dataset-model -Dtest='SandboxLayerATest,SandboxLayerBTest,SandboxLayerCTest'
```

两仓的测试名称集合必须相等（Java 方法名与 Python 函数名按"驼峰 vs 下划线"差异做映射后等价），否则 M9 视为未完成。

## 对 M1-M7 的依赖声明

- 依赖 M1：`ComposeQueryContext / AuthorityResolver`（用于构造 harness）
- 依赖 M2：`QueryPlan / from(...)` 入口
- 依赖 M3：`ComposeQueryDialect` + Layer A 宿主沙箱抛错点
- 依赖 M4：schema 推导（B-06 合法用例需要 schema 校验通过）

- 依赖 M7：`ScriptQueryTool`（可选；M9 也可以直接用 `SandboxRunner` 绕过工具入口）

若 M9 启动时 M6 尚未完成，B-03 用例的"参数化路径"断言可先以 `assertSandboxViolation(..., LAYER_B_INJECTION_SUSPECTED, ...)` 单路径通过；M6 完成后再改为 try-or-fallback 的双路径断言。
