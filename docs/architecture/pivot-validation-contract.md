# Pivot 校验与执行合同（#162）

## 范围与影响面

修复 `queryModel(mode=validate)` 和 `validateQuery` 在识别 Pivot 前检查普通
`columns` 的路由错误。Pivot 管线提取共用的请求和模型准备步骤，并复用主聚合、
轴域、树骨架、附属属性的请求构造器。执行继续使用原有 SQL 下放与内存整形路径。

校验走普通查询的受治理 SQL-only 编译，包含模型权限、逻辑字段白名单、物理列
黑名单、计算字段依赖和系统过滤；不执行主查询、辅助查询、轴成员枚举或结果缓存
读取。SQL 下放的可选能力不足仍允许既有内存降级；要求 SQL 的 cascade 必须在
校验阶段完成同一规划器的编译检查。

## 兼容性

- 普通查询仍要求非空 `columns`，Pivot 不要求顶层 `columns`。
- Pivot 与非空顶层 `columns`、`timeWindow` 仍互斥。已有顶层排序、分页及
  result-stage 限制保持不变；非法组合现在在 validate 和 execute 一致拒绝。
- `name` 为输入字段身份，`alias` 为结果身份；不把输出别名增加为输入同义词。
  Pivot 对外仍返回逻辑轴、指标名，结果值通过已有绑定映射读取。
- 普通 QM 维度白名单沿用维度组授权，树骨架的隐式 id/parentId 属于该组；
  物理列黑名单仍精确检查骨架 parentId、附属属性及计算字段的物理依赖。
- 保留 flat/grid/tree、轴 TopN/域分页、总计，以及 tree 总计关闭的既有行为。
  parentShare 和 baselineRatio 的分母范围及 first/last 基准合同不变。
- validate 使用 `VALIDATE` 权限动作，execute 使用调用上下文的执行动作；允许
  权限策略显式区分两者。相同策略下两条路径应接受或拒绝同一字段依赖。
- 原先被忽略的无效轴控制引用会提前拒绝；它们没有有效的数据计算合同。
- 多数据库回归另发现可加指标的内存 TopN 按单元格记录数截断。本轮同时修正为
  按父级分区聚合成员排名，窗口计数为成员数，并保留所选成员的全部列桶单元格。
  排名遵循指标的聚合语义；内存路径的轴控件在受治理的目标成员粒度重查，
  AVG/COUNT_DISTINCT/计算指标不能从单元格均值或记录数推断成员排名。
  cascade 必须 SQL 下放的限制不变。
- validate 成功表示静态计划可以编译且当前校验权限允许，不承诺运行时数据基数、
  数据库可用性、实际轴成员或数值结果。动态保护继续在 execute 生效。

## 验证顺序

1. 合法 Pivot、互斥请求、未知字段、输入名/输出别名及计算依赖回归。
2. 权限动作、模型拒绝、字段白名单/物理黑名单、系统过滤与辅助字段权限回归。
3. JDBC 观察器断言 validate 不准备或执行业务 SQL，并用 execute 验证观察器有效。
4. 使用固定小数据集逐项验算 tree 的直接节点值、parentShare 分母、baselineRatio
   first/last（含分页范围），再覆盖 Runtime HTTP validate→execute。
5. 回归通过后执行全量 Maven、引擎集成及 SQLite/MySQL 5.7/MySQL 8/
   PostgreSQL/SQL Server 测试。所有日志、XML、复现载荷和校验结果保存在外部
   releases 证据目录，保留上一轮证据及本轮失败尝试。

## 后续统一修复的合同与影响面

辅助汇总的批量执行必须使用请求准备时固定的 QueryModel JDBC 数据源，不能通过
外层 Compose 或默认 namespace 再次按名字查路由。旧执行端口保留；未实现固定
绑定执行的新适配器降级为受治理的逐 grain 查询。普通查询和 Compose 原有执行
入口不变。计算指标由现有表达式 AST 提取依赖，在目标汇总 grain 交给 SQL 编译器
计算；不在 Java 中重新猜测 SQL 函数或用简单算术替换聚合表达式。辅助 grain、
成员排名 grain 的静态编译纳入 validate，execute 使用自身权限动作做相同准备。
两者都必须在准备阶段检查字段依赖，validate 不执行业务 SQL。缓存命中沿用
目录/绑定/授权签名键及模型准备，不重复编译辅助 SQL；未命中时先静态编译
辅助依赖，再执行业务查询，保留既有缓存命中与目录刷新的生命周期合同。

TopN 的计数单位是每个父级分区内的成员，保留所选成员的所有交叉轴单元格。
Having 在成员聚合之后、窗口之前；行列轴选择基于相同的受治理事实范围，不能
因为另一轴已经截断而重算排名。内存降级会增加按受控轴层级执行的成员查询，
以获得 AVG、COUNT_DISTINCT 等精确聚合值；候选域触达安全上限时明确拒绝，
不能继续把截断结果当完整域。未知的内存重聚合不能退回按记录截断。

hierarchyMode=tree 只允许来自同一节点维度、由主键函数决定的行轴属性；额外的
独立分组在静态准备时拒绝，避免同一 nodeId 的不同分组覆盖。隐藏 id/parentId
从 QM 的源绑定与角色解析，沿用显式 name，输出 alias 不作为输入同义词。
树形 TopN/Having 按相邻父节点分区，移除成员时同时移除其子树；节点值仍是
自身直接聚合值，不递归累加后代。expandDepth=-1 全展开，0 仅展示根，N 展示
到第 N 层；深度只控制展示。树上的不可加排名暂不支持，在 validate 拒绝，
不改变无轴控件的直接值查询。实际邻接环、过深关系及骨架截断由 execute 拒绝，
不要求 validate 通过查询数据检测这些动态条件。原有 tree 总计关闭行为保留。

parentShare 的父值按原生指标声明的 SUM/COUNT/MIN/MAX 聚合；prePageParent
使用窗口之前、Having 之后的父级分母。无法证明聚合语义的计算指标不再乐观地
按 SUM 放行。baselineRatio first/last 始终使用有效列域的自然序，NULL 列值
不作为基准成员；展示排序和 start=0 不改变定义。外部基准索引明确提供后，
缺失成员/NULL 值/零分母均产生 NULL，不能回退到当前页的可见基准。

输入轴、属性、原生和派生指标需形成无冲突的输出 schema；重复坐标字段和
与轴重名的派生输出在查询前拒绝，保留 _sys_meta 与 _pivot_ 内部名字。
内部比例键使用带类型及长度的元组编码，辅助汇总缓存使用结构化坐标及汇总标志，
区分 NULL、字面量 null、数字与字符串。对外 tree cells 保留普通分量的旧键；
NULL 分量编码为 ~n，空串、含竖线或以 ~ 起始的字符串编码为 ~s 加 UTF-8 的
无填充 Base64URL，再以竖线拼接分量和指标名。特殊值使用方需识别该编码；
不能用无转义 split/join 反推原始值。遇到无法唯一表示的重复单元格明确报错。

这些变更局限于 Pivot 准备、辅助执行和结果算法。JSON 请求结构、普通查询、
name/alias 职责及常规树形单元格键不变；以前被忽略、错算或不能表示的组合
会改为正确执行或明确报错。properties 的 dim$property 路径合同不扩展，但其完整维度所有者、实际 QM 主键和
属性读取角色从元数据绑定获取，覆盖嵌套维度与显式改名；不能用路径首段猜测。
轴排序只能引用当前成员粒度中的坐标或已声明的 SQL 指标；另一轴或下级坐标
不在该粒度中，必须明确拒绝，不能按缺失值排序。成员查询只读取所需控制指标。
普通 tree 的 NULL 行节点保持实际 NULL，遵从 Runtime 的显式/省略 NULL 策略，
不再用业务字符串 __null__ 替代，避免与真实同名成员合并。
