# 技能编写器

本技能帮助您创建结构良好、遵循最佳实践和验证要求的 Claude Code 智能体技能。

## 何时使用本技能

在以下情况使用本技能：
- 创建新的智能体技能
- 编写或更新 SKILL.md 文件
- 设计技能结构和前置元数据
- 排查技能发现问题
- 将现有提示或工作流程转换为技能

## 操作指南

### 步骤 1：确定技能范围

首先，理解技能应实现的功能：

1.  **提出澄清问题**：
    - 此技能应提供什么具体能力？
    - Claude 应在何时使用此技能？
    - 它需要哪些工具或资源？
    - 这是供个人使用还是团队共享？

2.  **保持专注**：一个技能 = 一种能力
    - **好的**："填写PDF表单"、"Excel数据分析"
    - **太宽泛**："文档处理"、"数据工具"

### 步骤 2：选择技能位置

确定在何处创建技能：

**个人技能** (`~/.claude/skills/`)：
- 个人工作流程和偏好
- 实验性技能
- 个人生产力工具

**项目技能** (`.claude/skills/`)：
- 团队工作流程和约定
- 项目特定专业知识
- 共享实用工具（提交到git）

### 步骤 3：创建技能结构

创建目录和文件：

```bash
# 个人
mkdir -p ~/.claude/skills/技能名称

# 项目
mkdir -p .claude/skills/技能名称
```

对于多文件技能：
```
技能名称/
├── SKILL.md (必需)
├── reference.md (可选)
├── examples.md (可选)
├── scripts/
│   └── helper.py (可选)
└── templates/
    └── template.txt (可选)
```

### 步骤 4：编写 SKILL.md 前置元数据

创建包含必需字段的 YAML 前置元数据：

```yaml
---
name: 技能名称
description: 简要描述此功能的作用及使用时机
---
```

**字段要求**：

-   **name (名称)**：
    -   仅使用小写字母、数字、连字符
    -   最长 64 个字符
    -   必须与目录名匹配
    -   **好的**：`pdf-processor`，`git-commit-helper`
    -   **不好的**：`PDF_Processor`，`Git Commits!`

-   **description (描述)**：
    -   最长 1024 个字符
    -   包含**做什么**和**何时使用**
    -   使用用户会说的特定触发词
    -   提及文件类型、操作和上下文

**可选前置元数据字段**：

-   **allowed-tools (允许的工具)**：限制工具访问（逗号分隔列表）
    ```yaml
    allowed-tools: Read, Grep, Glob
    ```
    适用于：
    -   只读技能
    -   安全敏感的工作流
    -   范围有限的操作

### 步骤 5：编写有效的描述

描述对于 Claude 发现您的技能至关重要。

**公式**：`[功能] + [使用时机] + [关键触发词]`

**示例**：

✅ **好的**：
```yaml
description: 从 PDF 文件中提取文本和表格、填写表单、合并文档。在处理 PDF 文件或用户提及 PDF、表单或文档提取时使用。
```

✅ **好的**：
```yaml
description: 分析 Excel 电子表格、创建数据透视表并生成图表。在处理 Excel 文件、电子表格或以 .xlsx 格式分析表格数据时使用。
```

❌ **太模糊**：
```yaml
description: 帮助处理文档
description: 用于数据分析
```

**技巧**：
-   包含特定文件扩展名 (.pdf, .xlsx, .json)
-   提及常见用户短语（"分析"、"提取"、"生成"）
-   列出具体操作（而非通用动词）
-   添加上下文线索（"当...时使用"、"用于..."）

### 步骤 6：组织技能内容

使用清晰的 Markdown 章节：

```markdown
# 技能名称

简要概述本技能的功能。

## 快速开始

提供简单的示例以便立即上手。

## 使用说明

为 Claude 提供分步指导：
1.  第一步，明确操作
2.  第二步，预期结果
3.  处理边界情况

## 示例

展示具体的使用示例，包括代码或命令。

## 最佳实践

-   遵循的关键约定
-   需避免的常见陷阱
-   何时使用与不使用的场景

## 要求

列出任何依赖项或先决条件：
```bash
pip install 包名称
```

## 高级用法

对于复杂场景，请参阅 [reference.md](reference.md)。
```

### 步骤 7：添加支持文件（可选）

创建额外文件以实现渐进式披露：

**reference.md**：详细的 API 文档、高级选项
**examples.md**：扩展的示例和使用案例
**scripts/**：辅助脚本和实用工具
**templates/**：文件模板或样板代码

在 SKILL.md 中引用它们：
```markdown
有关高级用法，请参阅 [reference.md](reference.md)。

运行辅助脚本：
\`\`\`bash
python scripts/helper.py input.txt
\`\`\`
```

### 步骤 8：验证技能

检查以下要求：

✅ **文件结构**：
-   [ ] SKILL.md 存在于正确位置
-   [ ] 目录名与前元数据中的 `name` 匹配

✅ **YAML 前置元数据**：
-   [ ] 第 1 行以 `---` 开头
-   [ ] 内容前以 `---` 结束
-   [ ] 有效的 YAML（无制表符，正确缩进）
-   [ ] `name` 遵循命名规则
-   [ ] `description` 具体且 < 1024 字符

✅ **内容质量**：
-   [ ] Claude 的使用说明清晰
-   [ ] 提供了具体示例
-   [ ] 已处理边界情况
-   [ ] 列出了依赖项（如果有）

✅ **测试**：
-   [ ] 描述与用户问题匹配
-   [ ] 技能在相关查询时激活
-   [ ] 使用说明清晰且可操作

### 步骤 9：测试技能

1.  **重新启动 Claude Code**（如果正在运行）以加载技能
2.  **提出与描述匹配的相关问题**：
    ```
    你能帮我从这份 PDF 中提取文本吗？
    ```
3.  **验证激活**：Claude 应自动使用该技能
4.  **检查行为**：确认 Claude 正确遵循了使用说明

### 步骤 10：如有需要，进行调试

如果 Claude 不使用该技能：

1.  **使描述更具体**：
    -   添加触发词
    -   包含文件类型
    -   提及常见用户短语
2.  **检查文件位置**：
    ```bash
    ls ~/.claude/skills/技能名称/SKILL.md
    ls .claude/skills/技能名称/SKILL.md
    ```
3.  **验证 YAML**：
    ```bash
    cat SKILL.md | head -n 10
    ```
4.  **运行调试模式**：
    ```bash
    claude --debug
    ```

## 常见模式

### 只读技能

```yaml
---
name: code-reader
description: 读取和分析代码而不进行更改。用于代码审查、理解代码库或编写文档时。
allowed-tools: Read, Grep, Glob
---
```

### 基于脚本的技能

```yaml
---
name: data-processor
description: 使用 Python 脚本处理 CSV 和 JSON 数据文件。在分析数据文件或转换数据集时使用。
---

# 数据处理器

## 使用说明

1.  使用处理脚本：
\`\`\`bash
python scripts/process.py input.csv --output results.json
\`\`\`

2.  使用以下命令验证输出：
\`\`\`bash
python scripts/validate.py results.json
\`\`\`
```

### 具有渐进式披露功能的多文件技能

```yaml
---
name: api-designer
description: 遵循最佳实践设计 REST API。在创建 API 端点、设计路由或规划 API 架构时使用。
---

# API 设计器

快速开始：请参阅 [examples.md](examples.md)

详细参考：请参阅 [reference.md](reference.md)

## 使用说明

1.  收集需求
2.  设计端点（见 examples.md）
3.  使用 OpenAPI 规范进行记录
4.  对照最佳实践进行审查（见 reference.md）
```

## 技能作者的最佳实践

1.  **一个技能，一个目的**：不要创建全能技能
2.  **描述具体**：包含用户会说的触发词
3.  **说明清晰**：为 Claude 编写，而不是为人类
4.  **示例具体**：展示真实代码，而非伪代码
5.  **列出依赖项**：在描述中提及必需的包
6.  **与团队成员测试**：验证激活情况和清晰度
7.  **版本化您的技能**：在内容中记录变更
8.  **使用渐进式披露**：将高级细节放在单独文件中

## 验证清单

-   [ ] 描述包含"功能"和"时机"
-   [ ] YAML 前置元数据有效
-   [ ] 使用说明为分步式

## 故障排除

**技能未激活**：
-   使用触发词使描述更具体
-   在描述中包含文件类型和操作
-   添加带有用户短语的"当...时使用"子句

**多个技能冲突**：
-   使描述更独特
-   使用不同的触发词
-   缩小每个技能的范围

**技能有错误**：
-   检查 YAML 语法（无制表符，正确缩进）
-   验证文件路径（使用正斜杠）
-   确保脚本具有执行权限
-   列出所有依赖项

## 输出格式

创建技能时，我将：

1.  提出关于范围和要求的澄清问题
2.  建议技能名称和位置
3.  使用正确的前置元数据创建 SKILL.md 文件
4.  包含清晰的使用说明和示例
5.  根据需要添加支持文件
6.  提供测试说明
7.  对照所有要求进行验证

结果将是一个完整、可用的技能，遵循所有最佳实践和验证规则。
